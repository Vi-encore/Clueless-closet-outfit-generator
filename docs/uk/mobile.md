# Мобільні платформи: Android + iPhone

**Основний пристрій для розробки — Android.** iPhone — для періодичних перевірок: на ключових кроках і коли змінюється верстка.

Важливо: на iPhone **усі браузери працюють на рушії Safari (WebKit)**, тож перевірка в Safari покриває й Chrome на iPhone.

## Як тестувати

| | Android | iPhone |
|---|---|---|
| Доступ до dev-версії | Cloudflare Quick Tunnel (HTTPS), див. [poc.md](poc.md#доступ-з-телефона-через-тунель) | Те саме посилання, відкрити в Safari |
| Налагодження | Chrome DevTools через USB: на телефоні ввімкнути «Параметри розробника» → «Налагодження USB», на ПК відкрити `chrome://inspect` | Повноцінне налагодження Safari вимагає Mac. З Windows — консоль прямо на сторінці: бібліотека **Eruda**, підключається лише в dev-збірці (напр. за параметром `?debug`) |
| Встановлення PWA | Кнопка «Встановити» (своя, через подію `beforeinstallprompt`) | Вручну: Safari → «Поділитися» → «На початковий екран» |

## Особливості iPhone, які враховуємо одразу

| Що | Проблема | Що робимо |
|---|---|---|
| Встановлення | Немає `beforeinstallprompt`, кнопки «Встановити» не буде | Власна підказка з інструкцією — показувати на iPhone, якщо застосунок ще не встановлений (`display-mode: standalone`) |
| Іконка | iOS бере `apple-touch-icon` | Додати `apple-touch-icon` 180×180 окрім іконок маніфесту; для Android — ще maskable-іконка |
| «Чубчик» / Dynamic Island, смужка «додому» | Контент ховається під ними | `viewport-fit=cover` + відступи `env(safe-area-inset-*)` |
| Висота екрана | `100vh` на iPhone не враховує панелі браузера | Використовувати `100dvh` |
| Поля вводу | Safari збільшує масштаб, якщо шрифт поля < 16 px | Шрифт у полях вводу ≥ 16 px |
| Фото | iPhone знімає в HEIC | Перевірити, у якому форматі файл приходить з `<input capture>`; на бекенді приймати лише JPEG / PNG / WebP |
| Пам'ять | Safari суворіше обмежує пам'ять вкладки — важкі WASM-моделі (видалення фону) можуть гальмувати чи падати | Перевірити на iPhone якомога раніше (крок 9); запасний план — видаляти фон на сервері |
| Сховище браузера | Safari може очищати локальні дані сайту | Важливе — лише на сервері; локально — тільки кеш для швидкості (вже так за архітектурою) |
| Вхід після встановлення | PWA на головному екрані має окреме від Safari сховище й cookie | Після встановлення треба увійти заново — це нормально, варто підказати в інтерфейсі |
| Push-сповіщення | Лише для встановленої PWA (iOS 16.4+), дозвіл — тільки після дії користувача | Кнопка «Увімкнути сповіщення», а не запит одразу при відкритті |
| Фонові задачі | Background Sync на iPhone немає | Не покладатися: незавершені завантаження повторювати при наступному відкритті |
| Вібрація, Fullscreen API | На iPhone недоступні | Не використовувати для важливих функцій |

## Чеклист перевірки на iPhone

Проганяти на кроках 9 і 11 ([roadmap.md](roadmap.md)) і після помітних змін верстки:

- [ ] сторінки не ховаються під «чубчиком» і смужкою «додому»
- [ ] поля вводу не збільшують масштаб
- [ ] фото з камери й з галереї завантажуються, орієнтація правильна
- [ ] видалення фону працює й не падає
- [ ] застосунок додається на головний екран з правильною іконкою й відкривається без панелей Safari
- [ ] після встановлення можна увійти й залишатися в системі
