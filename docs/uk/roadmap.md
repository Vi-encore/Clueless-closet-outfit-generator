# Дорожня карта PoC

Код пишеться самостійно; до кожного кроку — детальні підказки (мета, що почитати, структура, ключові моменти, типові помилки, критерії готовності) і рев'ю написаного.

**Як працюємо:**
- **Почати крок** — «крок N» → підказки до нього.
- **Застрягли** — «підказка» → три рівні: напрямок → конкретніше → фрагмент коду.
- **Готово** — «перевір» → рев'ю ваших файлів (зауваження й питання, без переписування).
- **Потрібне готове рішення** — «покажи рішення».

## Закладки на майбутнє

Що закласти на ранніх кроках, щоб пізніші функції додавалися без переробок:

| Функція | Що закласти | Крок |
|---|---|---|
| Автотеги, перевірка перед покупкою | Переліки тегів у `core` + zod-схеми як єдине джерело правди; `TaggingProvider` (спершу ручний) | 1, 9 |
| Перевірка перед покупкою, валіза, «образ навколо речі» | Генератор — чиста функція з `mustInclude` / `exclude` | 1 |
| Чат, соціальне | `username`, UUID, `visibility`; перевірка токена й доступу — окремими методами; модулі `realtime` і `chat` окремо | 3, 4, 5, 6 |
| Статистика | `Item.price`, `Item.purchasedAt`; `wearCount` / `lastWornAt` оновлюються разом із `WearLog` | 3, 10 |
| Щоденник, «образ дня» | `User.timezone`; `WearLog.date` — календарна дата користувача | 3, 10 |
| Валіза, погода | `Item.warmth`; `WeatherProvider` (Open-Meteo) з кешем — коли знадобиться погода | 3, після PoC |
| Мобільний застосунок | Обгортки `camera` / `tokenStore` / `share`; `VITE_API_URL`; refresh-токен з cookie або з тіла запиту | 4, 8 |
| Try-on | `TryOnProvider`, `ReferencePhoto`, `TryOnJob` | 15, після PoC |
| Переклад інтерфейсу | У базі — коди (`blouse`), назви — у словнику інтерфейсу | 1, 8 |

## Кроки

### Крок 0 — середовище й каркас репозиторію
**Мета:** pnpm, Git, монорепо-структура.
**Що вивчите:** pnpm workspaces.
**Готово, коли:**
- [ ] `pnpm -v` працює
- [ ] є `apps/`, `packages/`, `pnpm-workspace.yaml`, кореневий `package.json`
- [ ] `.gitignore`, `.gitattributes`, перший коміт

### Крок 1 — `packages/core`: типи й перші правила оцінки
**Мета:** доменні типи (`Item`, `Occasion`, `Outfit`) і кілька чистих функцій оцінки.
**Що вивчите:** TypeScript-типи (union types, `as const`), Vitest, TDD.
**Закласти на майбутнє:** усі переліки тегів — `as const` масиви + zod-схеми, з яких виводяться типи, JSON Schema для Gemini і варіанти у формі (див. [auto-tagging.md](auto-tagging.md#єдине-джерело-правди--переліки-в-core)); генератор приймає речі як вхідні дані (сам у базу не ходить) і підтримує опції `mustInclude` / `exclude` — на цьому пізніше будуються «образ навколо речі», перевірка перед покупкою й валіза (див. [outfit-algorithm.md](outfit-algorithm.md#інтерфейс-генератора)).
**Готово, коли:**
- [ ] типи описані за [data-model.md](data-model.md)
- [ ] функції оцінки кольору й формальності + тести до них
- [ ] `pnpm --filter @closet/core test` зелений

### Крок 2 — NestJS: перший API
**Мета:** проєкт `apps/api`, `GET /health`, конфігурація з `.env`, глобальна валідація.
**Що вивчите:** модулі, контролери, сервіси, dependency injection, `ConfigModule`, `ValidationPipe`, DTO.
**Готово, коли:**
- [ ] `GET /health` відповідає
- [ ] невалідний DTO повертає 400 з поясненням

### Крок 3 — PostgreSQL + Prisma
**Мета:** Postgres у Docker Compose (або Neon), схема `User` і `Item`, міграції, `PrismaService`.
**Що вивчите:** Docker Compose, Prisma schema, міграції, lifecycle-хуки Nest.
**Закласти на майбутнє:** `User.username` (унікальний); усі id — UUID; дати — `timestamptz`; `Item.visibility` = `private` за замовчуванням; необов'язкові `Item.price` і `Item.purchasedAt` (для статистики); `User.timezone` (щоденник, «образ дня»).
**Готово, коли:**
- [ ] `docker compose up` піднімає базу
- [ ] перша міграція застосована, таблиці видно в Prisma Studio

### Крок 4 — авторизація
**Мета:** реєстрація, вхід, access + refresh токени, захищені маршрути.
**Що вивчите:** argon2, JWT, Passport-стратегії, guards, кастомний декоратор `@CurrentUser()`.
**Закласти для чату:** перевірка access-токена — окремий метод сервісу, а не лише всередині Passport-стратегії, щоб його перевикористав WebSocket-gateway.
**Готово, коли:**
- [ ] реєстрація → вхід → доступ до захищеного маршруту з токеном
- [ ] без токена — 401; refresh видає нову пару токенів

### Крок 5 — гардероб: CRUD речей
**Мета:** створення / перегляд / зміна / архівування речей з перевіркою власника.
**Що вивчите:** шари контролер → сервіс → Prisma, фільтри запитів, e2e-тести (Supertest).
**Закласти для чату:** перевірки доступу («чи може цей користувач бачити цю річ») — окремі методи сервісу, щоб перевикористати їх, коли річ пересилатимуть у чат.
**Готово, коли:**
- [ ] CRUD працює лише для своїх речей
- [ ] e2e-тест: користувач B не бачить і не змінює речі користувача A

### Крок 6 — друзі й чат (бекенд)
**Мета:** друзі (пошук за `username`, запит, прийняття) і чат між друзями: Socket.IO-gateway, кімнати, збереження повідомлень, історія через REST.
**Що вивчите:** WebSocket, Nest gateways, авторизація з'єднань, кімнати, підтвердження доставки (acks), пагінація курсором. Деталі — у [social.md](social.md#як-влаштований-чат).
**Готово, коли:**
- [ ] два користувачі стають друзями
- [ ] повідомлення доходять наживо (перевірка через Postman — він уміє Socket.IO) і зберігаються в базі
- [ ] не-учасник розмови не може ні читати, ні писати в неї
- [ ] після перепідключення підтягуються пропущені повідомлення

### Крок 7 — фото: Backblaze B2
**Мета:** бакет, presigned URLs для завантаження й перегляду, `StorageService`.
**Що вивчите:** S3 API (`@aws-sdk/client-s3`), presigned URLs, CORS бакета.
**Готово, коли:**
- [ ] файл завантажується напряму в B2 за presigned URL
- [ ] API віддає посилання на перегляд лише власнику

### Крок 8 — клієнт: React + Vite
**Мета:** `apps/web`, роутинг, вхід, список речей, екрани друзів і чату. Одразу mobile-first, `VITE_API_URL`, обгортки для платформних функцій (див. [architecture.md](architecture.md#мобільний-застосунок-pwa-зараз-магазини--через-capacitor)).
**Інтерфейс:** Tailwind + 98.css у каскадному шарі `components`, піксельний шрифт з кирилицею, компоненти `Window` і `Taskbar`, тема «Clueless» (див. [ui.md](ui.md)).
**Що вивчите:** робота з токенами на клієнті, API-клієнт, проксі Vite, адаптивна верстка, каскадні шари CSS.
**Готово, коли:**
- [ ] вхід / вихід, список своїх речей
- [ ] чат між двома акаунтами працює в браузері й на телефоні
- [ ] екрани у ретро-стилі; утиліти Tailwind перебивають 98.css; українські написи — піксельним шрифтом, а не Arial

### Крок 9 — додавання речі з телефона
**Мета:** камера → видалення фону → WebP → завантаження → форма тегів.
**Що вивчите:** `<input capture>`, `@imgly/background-removal`, canvas, `toBlob`.
**Закласти для автотегів:** форма тегів будується з переліків `core` і вміє приймати `TagSuggestion`; у Nest — `TaggingProvider` з ручною реалізацією; кольори рахуються з пікселів вирізаного фото.
**Готово, коли:**
- [ ] річ додається з телефона з вирізаним фоном
- [ ] пройдено [чеклист iPhone](mobile.md#чеклист-перевірки-на-iphone) для камери й видалення фону

### Крок 10 — генератор образів
**Мета:** `POST /outfits/generate` на основі `core`, екран генерації, 2D-лялька, «вдягнуто сьогодні» (`WearLog`), «образ навколо цієї речі» (`mustInclude`).
**Що вивчите:** інтеграція пакета монорепо в Nest, canvas-композиція, транзакції.
**Закласти для статистики й щоденника:** «вдягнуто сьогодні» створює `WearLog` і оновлює `wearCount` / `lastWornAt` в одній транзакції; дата — календарна, в часовому поясі користувача.
**Готово, коли:**
- [ ] обрати нагоду → отримати образ → «ще варіант» / лайк / зберегти / «вдягнуто сьогодні»
- [ ] з картки речі — «скласти образ з цією річчю»

### Крок 11 — PWA і тест на телефоні
**Мета:** маніфест, іконки, service worker, Cloudflare Quick Tunnel.
**Що вивчите:** PWA, HTTPS-вимоги браузерів.
**Готово, коли:**
- [ ] застосунок встановлюється на Android (своя кнопка «Встановити») і на iPhone (підказка з інструкцією)
- [ ] пройдено весь [чеклист iPhone](mobile.md#чеклист-перевірки-на-iphone)

> **Віха: ядро PoC готове** — гардероб, генератор, чат, застосунок на телефоні.

### Крок 12 — щоденник образів
**Мета:** до «вдягнуто сьогодні» — фото себе в образі (необов'язково) і нотатка; календар за місяць; «рік тому ви вдягали…».
**Що вивчите:** робота з датами й часовими поясами, календарна сітка, галерея з лінивим завантаженням фото.
**Готово, коли:**
- [ ] у календарі видно, що вдягалося кожного дня, з фото
- [ ] на головному екрані — спогад «рік / місяць тому», якщо є запис

### Крок 13 — статистика гардероба
**Мета:** вартість одного вдягання (ціна / кількість), «не вдягалося N днів — віддати?», найчастіше вдягане, розподіл за кольорами й категоріями, частка гардероба, що використовується.
**Що вивчите:** SQL-агрегації (Prisma `groupBy`, за потреби — сирий SQL), графіки (напр. Recharts або Chart.js).
**Готово, коли:**
- [ ] екран статистики з 3–4 показниками й графіками
- [ ] список «давно не вдягалося» з дією «архівувати»

### Крок 14 (опційно) — своя основа ляльки
**Мета:** спершу манекен за мірками (зріст, обхвати → SVG-силует і якорі), потім власне фото: фото на повний зріст → видалення фону → автоматичні якорі (MediaPipe Pose Landmarker) → ручне доправлення маркерів. Деталі — [try-on.md](try-on.md#манекен-за-вашими-параметрами).
**Що вивчите:** генерація SVG-контурів (криві Безьє), ML-моделі в браузері, робота з координатами.
**Готово, коли:**
- [ ] введені мірки змінюють силует наживо
- [ ] образ показується на манекені за мірками і на власному фото
- [ ] речі, підігнані на стандартному манекені, сідають на інші основи без повторної підгонки

### Крок 15 (опційно) — AI
**Мета:** автотеги через Gemini free tier зі структурованою JSON-відповіддю ([auto-tagging.md](auto-tagging.md)); кілька AI-примірок через публічне демо на Hugging Face.
**Готово, коли:**
- [ ] форма тегів заповнюється автоматично
- [ ] `TryOnProvider` з реалізацією для HF Space

## Після PoC

- **Соціальне й реальний час.** Друзі й базовий чат уже в PoC (кроки 6 і 8). Далі: обране → SSE для статусу try-on → пересилання речей / образів у чат → чат щодо позичання → «порадь образ» → оцінки. Деталі — у [social.md](social.md#порядок-від-простого-до-складного).
- **Перевірка перед покупкою** і **валіза в подорож** — див. [features.md](features.md).
