# Автотеги: розпізнавання речі з фото

## Коротко

- **Звертаємось до Gemini на безкоштовному тарифі.** Потрібен лише Google-акаунт і ключ з [AI Studio](https://aistudio.google.com/), картка не потрібна.
- **Формат відповіді фіксуємо заздалегідь:** JSON за нашою схемою (structured output). Модель не може відповісти довільним текстом — лише об'єктом, який можна одразу підставити у форму.
- **Модель лише пропонує теги.** Користувач перевіряє їх у формі; у базу пишемо тільки після підтвердження.

## Єдине джерело правди — переліки в `core`

- Усі допустимі значення (слоти, типи, візерунки, тканини, стилі, нагоди…) — `as const` масиви в `packages/core`.
- З них виводяться: TS-типи, zod-схема `TagSuggestion`, JSON Schema для Gemini (у zod 4 — `z.toJSONSchema()`), валідація DTO в Nest, варіанти у формі на клієнті. Додали новий тип речі — він з'явився скрізь.
- У базі зберігаються **коди** (`blouse`, `silk`), а українські назви — у словнику інтерфейсу. Тоді переклад чи перейменування не зачіпають дані.

## Формат відповіді (чернетка)

```json
{
  "name": "Біла атласна блуза",
  "slot": "top",
  "type": "blouse",
  "pattern": "solid",
  "fabricType": "satin",
  "materials": [{ "material": "silk" }],
  "fit": "regular",
  "length": "regular",
  "seasons": ["spring", "summer", "autumn"],
  "warmth": 2,
  "formality": 3,
  "styles": ["classic", "romantic"],
  "occasions": ["work", "date"],
  "uncertain": ["materials", "fabricType"]
}
```

- `uncertain` — поля, в яких модель не впевнена; у формі вони підсвічуються для перевірки. `materials` — завжди тут: склад видно лише на етикетці.
- Те, чого модель не може визначити, — `null`.
- `name` — єдине поле довільним текстом (українською, це вказано в промпті); решта — коди з переліків.
- **Кольори модель не визначає** — їх рахуємо самі з пікселів вирізаного фото (`node-vibrant` / `colorthief`): точніше й безкоштовно.
- `rise` (посадка), `avoidOccasions`, бренд, розмір, ціна — лише вручну.
- Повний перелік полів — [data-model.md](data-model.md#item).

## Потік

1. Клієнт уже має вирізане фото (крок 9). Паралельно:
   - рахує кольори з пікселів (на клієнті);
   - зменшує фото до ~512 px → `POST /ai/tag-suggestions` (multipart, ≤ 1 МБ). Якщо користувач уже обрав слот — передається як підказка (`slotHint`), це підвищує точність. Для розпізнавання фото ніде не зберігається.
2. Nest перевіряє добовий ліміт (`UsageCounter`, `auto_tag`) → `TaggingProvider.suggest(image, hints)`.
3. `GeminiTaggingProvider`: промпт + зображення + JSON Schema → відповідь → **перевірка zod-схемою**. Відповіді моделі не довіряємо навіть зі схемою: значення можуть бути недоречними (напр. `type` не з того слоту). Невалідні поля → `null`.
4. Клієнт отримує `{ suggestion, taggingVersion }` → **форма заповнюється, але повністю редагована**:
   - поля від AI позначені маленьким значком «AI», невпевнені — підсвічені;
   - багатозначні поля (сезони, стилі, нагоди) — «чипси»; для сезонів — кнопка «Всесезонна»;
   - обов'язкові лише `slot` і `type` — можна зберегти швидко й дозаповнити пізніше.
5. Користувач перевіряє → звичайний `POST /items`; разом зберігаються `aiSuggestion` і `taggingVersion` — щоб потім порівняти, що AI запропонував і що людина виправила.

Якщо AI недоступний (ліміт, немає мережі) — та сама форма, просто порожня.

Для [перевірки перед покупкою](features.md#перевірка-перед-покупкою) — той самий ендпоінт; річ не зберігається (або зберігається зі статусом `wishlist`).

## Провайдери

`TaggingProvider` — інтерфейс, як `TryOnProvider`:
- **`ManualTaggingProvider`** — повертає порожню пропозицію. На кроці 9 форма заповнюється вручну, але вже за тим самим форматом.
- **`GeminiTaggingProvider`** — крок 15.
- **Пізніше, за потреби** — локальна vision-модель (напр. через Ollama) або платний тариф Gemini.

## Безкоштовний тариф: обмеження

- **Ліміти запитів — на ключ, тобто спільні для всіх користувачів.** Тому: добовий ліміт на користувача; якщо квоту вичерпано (HTTP 429) — тихий перехід на ручну форму.
- **Дані:** на безкоштовному тарифі Google може використовувати запити для покращення своїх продуктів. Надсилаємо лише фото речей (ніколи — фото людей) і згадуємо це в політиці конфіденційності. Для продакшну з багатьма користувачами — платний тариф (≈ $0.0002 за річ).
- **Модель — у конфігурації** (`GEMINI_TAGGING_MODEL`): назви й тарифи змінюються часто.
- **Точні назви полів SDK** для структурованої відповіді звірити з [актуальною документацією](https://ai.google.dev/gemini-api/docs/structured-output) на кроці 15 — API розвивається. Gemini підтримує підмножину JSON Schema: `type`, `properties`, `required`, `enum`, `items`; дуже великі чи глибоко вкладені схеми може відхилити.

## Версіонування

`taggingVersion` (версія промпту + схеми) повертається разом із пропозицією — щоб згодом перезапустити розпізнавання для старих речей або порівняти якість версій.

## Тестування

- У тестах Gemini не викликається — мок `TaggingProvider`.
- Набір із 10–20 фото своїх речей з очікуваними тегами — щоб порівнювати версії промпту.
