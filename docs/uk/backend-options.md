# Варіанти бекенду й хмари (довідка)

Що розглядалося і чому обрано **NestJS + PostgreSQL (Neon) + Cloudflare R2**. Дані про тарифи — станом на вересень 2026.

## AWS Free Tier: що насправді безкоштовно

Для нових акаунтів (модель діє з липня 2025):

- **Кредити:** $100 одразу + до $100 за виконання завдань (запустити EC2, створити бюджет, базу RDS тощо).
- **Free plan** триває 6 місяців або доки не закінчаться кредити. Поки ви на ньому, гроші не списуються.
- **Після завершення** AWS закриває акаунт; дані зберігаються 90 днів — за цей час можна перейти на платний план.
- **Always Free** (назавжди, з місячними лімітами) — лише частина сервісів, напр. DynamoDB (25 ГБ) і Lambda (1 млн запитів / міс).
- **S3 і RDS** у нових акаунтах фактично оплачуються з кредитів, а після них — за звичайними цінами (найменший RDS Postgres — порядку $15+ / міс).

**Висновок:** AWS підходить, щоб повчитися, але безкоштовно на роки там працюють лише сервіси з Always Free (DynamoDB, Lambda), а вони під цей проєкт підходять погано.

Джерела: [AWS Free Tier docs](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier.html), [AWS Free Tier FAQ](https://aws.amazon.com/free/free-tier-faqs/).

## Чому не DynamoDB

DynamoDB — NoSQL-база типу «ключ-значення»:
- таблиці проєктуються під заздалегідь відомі запити (access patterns);
- з'єднань (JOIN) немає;
- кожен новий тип запиту — новий індекс або переробка схеми.

У нас дані реляційні: користувачі ↔ речі ↔ образи ↔ історія носіння ↔ позичання між користувачами ↔ друзі. Запит «речі, які не вдягалися 30 днів і зараз не позичені» — природний для SQL і незручний для DynamoDB.

До того ж вивчати одночасно NestJS і DynamoDB (single-table design) — забагато нового за раз.

## Supabase: що це й наскільки складно

Supabase — «бекенд як сервіс» навколо PostgreSQL:

| Частина | Що робить |
|---|---|
| Postgres | Повноцінна база + веб-панель (редактор таблиць, SQL-консоль) |
| Auth | Реєстрація, вхід, OAuth (Google, Apple), magic links; видає JWT |
| Автоматичний API | Кожна таблиця одразу доступна через REST. З клієнта: `supabase.from('items').select('*').eq('status', 'available')` |
| Row Level Security | Правила доступу прямо в базі, SQL-політиками: `create policy "own items" on items using (auth.uid() = owner_id);` |
| Storage | Файли з такими самими політиками доступу |
| Realtime | Підписка на зміни в таблицях |
| Edge Functions | Серверні функції на TypeScript (Deno) — для коду із секретними ключами |

**Наскільки складно:**
- **Старт — 1–3 дні**, якщо знаєте основи SQL: таблиці, вхід, CRUD з клієнта.
- **Найскладніше — RLS.** Безпека описується SQL-політиками. Помилка в політиці або відкриває чужі дані, або мовчки повертає порожній результат — налагоджувати це незвично.
- **Складна логіка** переїжджає в SQL-функції, тригери або Edge Functions, тобто розпорошується між базою й функціями.
- **Що вивчаєте:** переважно Postgres і RLS — корисно, але мало про архітектуру бекенду.

**NestJS для порівняння:**
- **Основи — 1–2 тижні:** модулі, контролери, сервіси, dependency injection, DTO й валідація, guards, pipes.
- **Ще кілька тижнів:** авторизація, ORM і міграції, завантаження файлів, тести.
- **Що вивчаєте:** шарову архітектуру й DI — ті самі ідеї, що в Spring, .NET, Angular. Навичка переноситься на будь-який бекенд.

| Задача | Supabase | NestJS |
|---|---|---|
| Реєстрація / вхід | Готово | Пишете самі (Passport + JWT) |
| CRUD | Готово (автоматичний API) | Контролер + сервіс + DTO |
| Доступ лише до своїх даних | RLS-політики в SQL | Перевірки в сервісах + guards |
| Завантаження фото | Готово (Storage) | Presigned URLs до R2 / S3 |
| Виклик AI із секретним ключем | Edge Function | Звичайний сервіс у Nest |
| Хостинг | Включено | Окремо (Render, VPS, AWS) |

Можна й поєднати: Nest як бекенд + Supabase лише як хостинг Postgres і файлів. Але безкоштовний проєкт Supabase ставиться на паузу після 7 днів без активності й потребує ручного відновлення, а Neon прокидається сам — тому для бази обрано Neon.

## Де хостити NestJS

| Варіант | Ціна | Нюанси |
|---|---|---|
| Render (free web service) | 0 | Засинає без запитів; перший запит після сну повільний |
| AWS EC2 | З кредитів, до 6 міс | Корисна практика AWS; далі платно |
| AWS Lambda | Always Free (1 млн запитів / міс) | Nest треба адаптувати під serverless, є холодні старти — не для першого проєкту |
| Дешевий VPS (Hetzner тощо) | Кілька євро / міс | Стабільно; практика Docker і Linux |

**Рекомендація:** розробка локально → Render на старті → VPS, коли з'являться реальні користувачі.
