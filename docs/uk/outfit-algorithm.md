# Алгоритм підбору образів

## Як це зроблено у відео-натхненні (довідково)

1. Усі пари «верх × низ» — декартів добуток гардероба.
2. Жорсткі фільтри під нагоду: топ для вечірки, спортивні штани чи короткі шорти не потрапляють в образи для роботи.
3. Оцінка решти: чи поєднуються кольори, чи збалансовані силуети, чи пасують стилі й тканини.
4. Вибір: беруться 14 найкращих, до балу кожного додається випадковий шум ±2.5, лишаються 7, і з них обирається один зважено-випадково (вага = `max(1, score − min + 1)²`). Так образ щоразу хороший, але не однаковий.

## Наш підхід

### Слоти образу

Образ будується за одним із шаблонів:
- **верх + низ**
- **цільна річ** (сукня, комбінезон)

Плюс опційні шари: верхній одяг (за погодою / нагодою), взуття, аксесуар.

MVP: лише базові шаблони. Шари додаються пізніше «жадібно»: спершу обирається базовий образ, потім до нього — найкраще взуття / верхній одяг. Так кількість комбінацій не росте як добуток усіх категорій.

### Кроки

1. **Кандидати.** Речі користувача зі статусом `available` (не в пранні, не в архіві) без активного позичання, що підходять нагоді. Пізніше — ще й речі, позичені цьому користувачу.
2. **Комбінації** за шаблонами.
3. **Жорсткі фільтри** — відкидаємо, якщо:
   - річ має цю нагоду в `avoidOccasions`;
   - формальність речей відрізняється більше ніж на 2;
   - (пізніше) річ не за погодою.
4. **Оцінка** — зважена сума компонентів:

   | Компонент | Що перевіряє |
   |---|---|
   | Колір | Нейтральні (чорний, білий, сірий, беж, денім) — з усім; решта — за колірним колом; не більше одного яскравого акценту й одного принта |
   | Силует | Облягаюче + об'ємне — добре; два об'ємні — штраф; кроп-топ + висока посадка — бонус |
   | Формальність | Наскільки образ близький до цільової формальності нагоди |
   | Стиль | Спільні стильові теги |
   | Фактура / сезон | Узгодженість фактур (атлас + грубий трикотаж — штраф), теплоти (`warmth`) і сезонів (`seasons`) |
   | Новизна | Штраф за речі / образи, вдягнуті нещодавно |
   | Вподобання | Бонус або штраф за лайки / дизлайки таких самих чи схожих пар |

   Порожні поля не штрафуються: компонент, для якого бракує даних, дає 0.

5. **Вибір.** Топ-K + шум + зважений рандом, як у відео. «Ще варіант» виключає вже показані образи.
6. **Пояснення.** Кожен образ зберігає `breakdown` — бали за компонентами. Це дає змогу показати «чому саме цей образ» і зручно налаштовувати ваги.

### Нагоди — це дані, а не код

Нагода (`Occasion`) зберігається в базі, тож можна додавати свої («аеропорт», «співбесіда»). У кожної нагоди є:
- цільова формальність (1–5);
- заборонені / обов'язкові властивості (напр. «робота» — без спортивного стилю й міні);
- ваги компонентів оцінки (для «вечірки» колір і стиль важливіші, для «аеропорту» — комфорт).

## Дані

Поля речі, на яких рахується оцінка, а також `Outfit`, `WearLog` і `Occasion` описано в [data-model.md](data-model.md).

## Де виконується

Алгоритм живе в `packages/core` — чистий TypeScript без залежностей від Nest і бази. API (`POST /outfits/generate`) збирає вхідні дані (доступні речі, історію, реакції, нагоду) і викликає `core.generateOutfit()`. Детальніше — в [architecture.md](architecture.md#алгоритм-працює-на-сервері).

## Інтерфейс генератора

Генератор — чиста функція: отримує все потрібне аргументами й нічого не читає з бази сам. Приблизна форма (назви — орієнтир, не остаточний код):

```ts
generateOutfits(input: {
  items: Item[];            // доступні речі (можуть включати «віртуальні», яких нема в базі)
  occasion: Occasion;
  history?: WearHistory;    // для штрафу за новизну
  reactions?: Reactions;    // лайки / дизлайки
  mustInclude?: ItemId[];   // образ обов'язково містить ці речі
  exclude?: ItemId[];       // ці речі не використовувати (вже показані, в пранні…)
  limit?: number;
}): ScoredOutfit[]
```

На цьому будуються:
- **«Образ навколо цієї речі»** — `mustInclude: [itemId]` (крок 10).
- **Перевірка перед покупкою** — віртуальна річ у `items` + `mustInclude` ([features.md](features.md#перевірка-перед-покупкою)).
- **Валіза** — генератор на обмеженому наборі речей ([features.md](features.md#валіза-в-подорож)).

## Навчання на відгуках (пізніше)

Спершу — прості поправки: лайк пари дає їй бонус, дизлайк — штраф. Згодом можна підлаштовувати ваги компонентів під конкретну людину. Машинне навчання для цього не потрібне.
